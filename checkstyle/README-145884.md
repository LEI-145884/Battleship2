# Checkstyle quality gate: constant names

**145884 - Lukasz Swiecicki**

## Chosen identifier type: constants (`ConstantName`)

Constants (`static final` fields, including interface fields) must follow
**UPPER_SNAKE_CASE**, as required by the
[Google Java Style Guide §5.2.4](https://google.github.io/styleguide/javaguide.html#s5.2.4-constant-names)
and the
[Oracle Java Naming Conventions](https://www.oracle.com/java/technologies/javase/codeconventions-namingconventions.html):

```
^[A-Z][A-Z0-9]*(_[A-Z0-9]+)*$
```

The name starts with an uppercase letter, contains only uppercase letters and digits,
and words are separated by exactly one underscore (no leading, trailing or double `_`).

| Valid | Invalid |
|-------|---------|
| `BOARD_SIZE`, `NUMBER_SHOTS`, `MAX_SHIPS`, `LOGGER` | `maxShips`, `Max_Ships`, `MAX__SHIPS`, `MAX_SHIPS_`, `_MAX` |

## Files

| File | Purpose |
|------|---------|
| [`checkstyle-145884.xml`](../checkstyle-145884.xml) | Checkstyle configuration with only the `ConstantName` rule (applied to public, protected, package and private constants) |
| [`.github/workflows/checkstyle-naming-145884.yaml`](../.github/workflows/checkstyle-naming-145884.yaml) | GitHub Actions workflow using [`nikitasavinov/checkstyle-action@1.0.0`](https://github.com/marketplace/actions/run-java-checkstyle) (Checkstyle 13.9.0) |

The workflow runs on every pull request (and on push to `main`). It uses
`filter_mode: nofilter`, so the **whole code base** is checked (not only the lines
changed in the PR), and `fail_level: any`, so the job fails when there is at least one
violation. Each violation is reported as an annotation with the file and line.
The `main` branch is protected by a rule that requires the
`checkstyle-constant-name-145884` check to pass before a pull request can be merged.

When the gate was first run, it found one real violation already in the project:
`private static final ObjectMapper mapper` in `ScoreboardService.java:13`, which was
renamed to `MAPPER`.

## Runs

- Passing run (renamed to `MAX_SHIPS`): PASSED_RUN_URL
- Pull request: PR_URL

## What Checkstyle cannot verify

Checkstyle only checks the *form* of a name against a regular expression; it cannot tell
whether the name is meaningful or describes what the constant represents (e.g. `X_1` or
`VALUE` pass, just like `BOARD_SIZE`). It also cannot decide whether a `static final`
field is really a constant in the Google sense (a deeply immutable value): a mutable
`static final ObjectMapper` or `List` is still forced into UPPER_SNAKE_CASE, and
local `final` variables that act as constants are not checked at all. Finally, it does not
check the language of the identifiers (the project mixes Portuguese and English names,
e.g. `GALEAO` and `BOARD_SIZE`) nor consistency of vocabulary across the code base.
