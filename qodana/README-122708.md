# Qodana quality gate: Long Parameter List (122708)

Este gate deteta instâncias do cheiro **Long Parameter List** (Fowler) no BattleShip2 com o Qodana Community for JVM, executado no GitHub Actions.

## Ficheiros

| Ficheiro | Função |
|---|---|
| `.github/workflows/qodana-smell-122708.yaml` | Workflow: corre em pull requests, em pushes para `main` e manualmente |
| `qodana-122708.yaml` | Configuração do linter (`jetbrains/qodana-jvm-community:2026.2`), perfil e condição de falha (`severityThresholds.any: 0`) |
| `.qodana/profiles/profile-122708.xml` | Perfil de inspeção usado pelo gate: todas as inspeções do linter desativadas, exceto as duas abaixo |
| `.qodana/profiles/profile-122708.yaml` | Versão YAML equivalente do perfil; o gate usa o XML |

Versões: `JetBrains/qodana-action@v2026.2` e linter `jetbrains/qodana-jvm-community:2026.2`.

## 1. Tabela de mapeamento

| Cheiro (Fowler) | Inspeção no IDE | ID da inspeção | Métrica / limiar | Limitações |
|---|---|---|---|---|
| Long Parameter List | Method with too many parameters | `ParametersPerMethod` | Número de parâmetros; opção `m_limit`, por omissão 5 (reporta quando o número **excede** o limite) | Limiar absoluto, não relativo ao sistema; métodos que sobrescrevem um super método não são reportados |
| Long Parameter List | Constructor with too many parameters | `ParametersPerConstructor` | Número de parâmetros; opção `m_limit`, por omissão 5; opção `ignoreScope` (omissão: nenhuma) | Limiar absoluto, não relativo ao sistema |

Valor usado neste projeto: `m_limit: 4`, ou seja, reporta métodos e construtores com 5 ou mais parâmetros (alinhado com o perfil `NOPM >= 4` do MetricsTree). Os IDs `ParametersPerMethod` e `ParametersPerConstructor` constam da lista de inspeções do linter usada no perfil XML.

## 3. Notas de configuração

- **`pr-mode: false` no workflow.** Em modo pull request, o Qodana volta ao commit base (merge-base com `main`) e procura aí a configuração. Como `qodana-122708.yaml` só existia no ramo do PR, a primeira execução falhou com `file "/data/project/qodana-122708.yaml" does not exist`. Com `pr-mode: false` o Qodana analisa o projeto inteiro tal como está no ramo.
- **Perfil em XML.** A ficha admite o perfil em YAML ou em XML. O XML lista todas as inspeções do linter e desativa todas menos as duas usadas, de modo a não depender do perfil base.

## 4. Reflexão

A ferramenta detetou o método com 9 parâmetros que introduzi de propósito (o gate falhou) e voltou a passar depois de o remover. A inspeção apenas conta parâmetros, por isso pode dar falsos positivos (por exemplo, um construtor de um objeto de dados) e falsos negativos (métodos que sobrescrevem um super método não são reportados, e agrupar parâmetros num objeto esconde a lista longa sem a eliminar). O resultado depende de duas escolhas absolutas: `m_limit` (4) define o que conta como cheiro e `any` (0) define quantos problemas o gate tolera. Face às estratégias do livro, que segundo a ficha usam limiares relativos e combinam várias métricas com condições lógicas, o Qodana só oferece um valor-limite absoluto por inspeção, pelo que este gate é apenas uma aproximação.
